Testing

Read this for: the test commands, the database they use, and what tests/test_layout.py fails on.

Source files: tests/test_layout.py, tests/test_authorization.py, apps/accounts/tests.py, apps/diary/tests.py, config/settings.py

From the repository root, with the virtualenv active and Postgres running:

python manage.py test
python manage.py test tests

Use Django's test runner and TestCase. Do not use pytest. Do not point tests at SQLite. The database settings are the Postgres variables in Configuration. Django creates a test database on that server.

python manage.py test discovers tests in installed apps and in the root tests package. python manage.py test tests runs the root package only. App tests belong in the app and run with the first command. apps/accounts/tests.py covers sign-in, reset, settings, registration, and the admin notices. apps/diary/tests.py covers the personal diary on every account-creation path, the role table, the Diaries page, entries, invitations, role changes, removal, leaving, and the day page. tests/test_authorization.py lists every product route and fails when a new URL name is missing. It requests each row as a normal page and with HX-Request, including signed out, non-member, Contributor, Editor, Owner, and staff. A refused diary or entry write leaves the row unchanged. A new route adds a row there in the same change.

Tests do not call a live AI provider, send real email, or write to production storage. Django's test runner swaps in the locmem mail backend, so mail.outbox holds the reset message and the change notices. Nothing in the runner stops a later test from calling an outside service.

Client.login() does not pass a request. The axes backend requires one, so a test posts the sign-in form or calls force_login.

Autosave checklist​

Server rules are covered by apps/diary/tests.py and tests/test_authorization.py. The browser does not have a test runner. Walk this list on a phone and on a desktop browser. There is no service worker. Offline means this page only.

  • Type a note and pause. The status goes Saving, then Saved. The address becomes /entries/<id>/. A blank box does not create an entry.
  • Turn the network off, type more, and see Offline (will retry). Turn it back on and see Saved. The text is the later wording.
  • Open the same entry in two tabs. Save a different wording in each. The second tab shows Conflict, the box still has what was typed there, and Load the saved entry and Copy your text both work.
  • Type without waiting for Saved, then follow a link or close the tab. The browser asks before leaving. Stay, wait for Saved, and leave again. The browser does not ask.
  • Sign out. On the sign-in page, this browser has no draft database. Sign back in and open Write. There is no offer to restore.
  • On your own device, type, turn the network off, and reload. The page offers to restore the newer copy. Restore puts it back. Discard leaves the saved wording.
  • Sign in with This is a shared device. Type with the network off and reload. The page does not offer a local copy.

Accessibility checklist​

Walk this on a phone and on a desktop browser. The app does not animate, so a reduced-motion setting should change nothing. Do not add a transition or animation without a prefers-reduced-motion override in app.css.

  • Header links, the footer Privacy link, buttons, calendar days, and checkbox rows are at least 44 pixels in one direction. On a 320-pixel-wide screen the calendar cells stay at least 44 pixels wide. The checkbox itself is smaller than 44 pixels; the labeled row is the target.
  • Tab from the skip link through the header, the page, and Privacy. The outline is visible. The skip link appears when it receives focus.
  • Text uses the tokens in theme_and_design_brief.md Section 3. A state is a word plus a color: Saving, Saved, Offline (will retry), Conflict, Error, Loading, Nothing written for this day, No days with entries, Page not found, Not allowed, and Something went wrong.
  • Turn the network off on the editor and see Offline. Open the same entry in two tabs and see Conflict, with Load the saved entry and Copy your text. Settings shows Saved after a change. A bad field keeps what was typed and shows the error in words.
  • Privacy is in the footer and on Settings. The page states the accepted risks and says backup and deletion details are to be published before launch.
  • The name in the header is the text wordmark. There is no icon.

What the layout tests check​

  • The app labels stay accounts and diary, and AUTH_USER_MODEL stays accounts.User.
  • The email is the login. The display name is required. Appearance defaults to system. Timezone defaults to UTC.
  • base.html, 403.html, 404.html, 500.html, diary/day.html, diary/browse.html, diary/month.html, diary/raw.html, diary/diary_view.html, diary/diaries.html, diary/entry_form.html, and accounts/privacy.html resolve.
  • The stylesheet, theme registry, theme script, HTMX script, and both Source Sans 3 files are discoverable.
  • Every mode declared in themes.json has a CSS block that defines every required token.
  • No color property below /* components */ uses a literal hex, rgb, or hsl color.
  • A signed-in / redirects to today's day page, which renders in light mode, with the theme script before the stylesheet, the HTMX config meta tag, the CSRF header, a skip link, a main landmark, a Privacy link, and the Loading indicator.
  • An unknown URL uses the 404 template when debug is off.
  • SiteSettings is one row and registration is closed.
  • createsuperuser stores a lowercased email, and a timezone must be an IANA name.
  • A superuser can open the user and site-settings admin pages.
  • The response sends the Content Security Policy and the other security headers, with no unsafe-inline.
  • check --deploy passes when debug is off, production mode is on, and an allowed host is set.
