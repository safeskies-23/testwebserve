Deploy

Read this for: publishing a new image and running it on the homelab.

Source files: Dockerfile, .github/workflows/image.yml, docker-compose.yml, .env.example

The running copy is Unraid. Dockhand starts docker-compose.yml. The app container is pebble-diary, from ghcr.io/safeskies-23/pebblediary:latest. Postgres 17 is pebble-diary-postgres. A push to main builds that image and tags it latest and the commit id. A push to develop does not. The workflow logs in to ghcr.io with the token GitHub creates for that run. Dockhand uses a separate registry login. The image does not contain .env.

The image runs collectstatic while it is built, with production mode on, so the static manifest exists. The app container runs python manage.py migrate and then Gunicorn on port 8000. Migrate applies pending migrations and leaves a current database unchanged. Pulling the image does not do this. Redeploy the stack with Pull images so Dockhand replaces the app container.

The app service sets DJANGO_PRODUCTION true. TLS ends at the reverse proxy on the proxy network, and the app container still speaks HTTP. Point the proxy at http://pebble-diary:8000, pass the original Host, and set X-Forwarded-Proto to https. Django then treats the request as secure, redirects plain HTTP to HTTPS, and sends HSTS for one year including subdomains. The allowed hosts in the example env are localhost, 127.0.0.1, and pebblediary.com. The image with this behavior is the one built after this change. Registration is off. There is no default account. The first account was created inside the container:

docker exec -it pebble-diary python manage.py createsuperuser

The command asks for an email, a display name, and a password. The email is the sign-in name.

Postgres is published on 127.0.0.1 only. The app reaches it at host postgres on the Compose network internal. The stack also joins an external Docker network named proxy, which must already exist. The host folder /mnt/user/appdata/pebble-diary is mounted at /postgresql/data. Postgres stores its files at /var/lib/postgresql/data, so that folder is not the database. The data for the running copy is inside the Postgres container. Recreating pebble-diary-postgres drops it.

An update is three moves:

  1. Commit on develop.
  2. Merge develop into main and push main. Wait until Actions is green.
  3. In Dockhand, redeploy the stack with Pull images.

Production mode also selects the SMTP mailer when DJANGO_EMAIL_BACKEND is empty. Homelab mail is not configured, so password reset on that copy still has nowhere to send a message.

Account erasure is python manage.py erase_deactivated_accounts inside the app container. Run it daily. A second run changes nothing more. The published backup window is 90 days after a row is erased. This copy does not keep database backups, and a restore drill is not part of it.
