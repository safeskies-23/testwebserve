HTMX and templates

Read this for: what every page extends, how the day page swaps its panel, how data-theme and data-mode are set, and what the Content Security Policy forbids.

Source files: templates/base.html, templates/403.html, templates/404.html, templates/500.html, apps/diary/views.py, apps/diary/urls.py, apps/diary/templates/diary/day.html, apps/diary/templates/diary/browse.html, apps/diary/templates/diary/month.html, apps/diary/templates/diary/raw.html, apps/diary/templates/diary/diary_view.html, config/theme.py, static/js/theme.js, static/css/themes.json, static/css/app.css, static/js/htmx.min.js, apps/diary/static/diary/autosave.js, config/settings.py

Every normal page extends templates/base.html. The 500 page does not, because it has to render when the usual context is unavailable. It hardcodes the same light-mode attributes and loads the stylesheet only.

Base template​

base.html loads static/js/theme.js in the head before static/css/app.css. HTMX is a self-hosted file at the end of the body, static/js/htmx.min.js. The editor script is diary/autosave.js, also a file. A signed-out page sets data-clear-drafts on the body so that script deletes this browser's drafts. There is no inline script and no inline style.

The htmx-config meta tag sets includeIndicatorStyles to false, so HTMX does not inject a style element. Indicator styles, when a screen needs them, go in app.css.

The body sets hx-headers so HTMX requests send X-CSRFToken. The day page is the screen that reads request.htmx. The write page is an ordinary form. A normal form also includes its own {% csrf_token %}. There is no inline event handler. A skip link points at the main landmark.

The header shows the wordmark. A signed-in person also gets a Pages nav (Write, Diaries, Settings) and a sign-out button. The footer links to /accounts/privacy/. Diary text uses entry-text, which keeps line breaks and stops at 65 characters. templates/403.html extends the base template and says the person cannot do that. It is the response when a member lacks an action. The 500 page does not extend the base template, so it has no footer. It shows the wordmark as text.

Primary buttons use the accent fill. Sign out, and the editor's conflict and restore actions, use quiet. Delete uses danger. Empty copy uses empty. A conflict and a newer local copy use notice. Form errors are the field's error list, in words and in the error color. Settings shows Saved after a change. The app does not animate.

Day page​

/ redirects to /d/<YYYY-MM-DD>/ for today in the signed-in person's timezone. The path uses an isodate converter in apps/diary/urls.py. A date that is not a real calendar day, such as February 31, is 404.

The page opens in Diary view. ?view=raw is Raw. Any other view value is 404. ?month=YYYY-MM shows that month's grid while keeping the selected day. A missing month is the day's own month. A month that is not YYYY-MM is 404. ?diary=<id> limits the entries, the calendar marks, and the list of days to one diary the person can read. Any other id is 404. Omitting it shows every readable diary.

Diary view shows that day's entries as separate paragraphs, oldest submission first. The text is escaped and is not rewritten. Raw view lists the same entries with the submission time in the person's timezone, the diaries they can see, and Edit when they are the current owner. A shared diary's name includes the word Shared, using the shared text on the shared-soft fill. An entry in a shared diary the person can read shows the writer's current display name in both views. An entry that is only in someone else's private diary is not on the page. A day with nothing to show says so, and Write for this day opens /entries/new/?date=<that day>. A date query that is not a real day is ignored, and the editor falls back to blank, which means today.

The month grid starts on Sunday. A day with an entry has a dot and the words "has entries" in its accessible name. Previous month, Next month, and Today keep the view and the diary filter. Days with entries lists every such day, newest first. That list is not paged.

#browse is boosted, so those links swap that region and push the URL. Write for this day and Edit are not boosted. While a boosted request is in flight, the panel shows Loading. Those indicator rules live in app.css, because the HTMX config turns indicator styles off. A normal request, and a history restore (HX-History-Restore-Request), return diary/day.html. An HTMX request returns diary/browse.html, including a title element that HTMX lifts into the document title. Both responses send Vary: HX-Request.

Who may see an entry is on Permissions. Saving one is on Entries and autosave.

Theme​

static/css/themes.json lists one theme, paper-moss ("Warm Paper & Moss"), with modes ["light"]. It is the default.

config/theme.py is a context processor. It sets:

  • data-theme to paper-moss
  • data-color-preference to the signed-in user's appearance, or system when nobody is signed in
  • data-mode to that preference when the theme has designed it, otherwise light
  • data-modes to the designed modes, comma-separated. Today that is light

static/js/theme.js runs before the stylesheet. When the preference is system, it follows prefers-color-scheme only among data-modes. The theme has no dark mode, so the script leaves the page in light mode and does not subscribe to later system changes. A stored preference of dark also stays light until that mode exists.

app.css opens with the Source Sans 3 faces, then one block, html[data-theme="paper-moss"][data-mode="light"], that defines every semantic token. Below the /* components */ marker, color properties use those variables. The layout test fails a literal color under that marker.

The docs site uses the same light values in sites/pebble-diary/src/css/custom.css. Its color-mode switch is off until a dark palette exists. CopperDraw's stylesheet stays in sites/copper-draw/.

Content Security Policy​

The policy is in Configuration. It allows scripts, styles, fonts, and images from this origin only. A new screen keeps that policy:

  • Do not add an inline script, an inline event handler, or an inline style.
  • Do not load a font, script, or image from another origin.
  • Keep HTMX's injected indicator styles off.

The 500 page loads no script, so a failure still has no inline-script exception.
