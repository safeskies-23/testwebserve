Permissions

Read this for: which function answers a role-table question, and when a request gets 404 or 403.

Source files: apps/diary/permissions.py, apps/diary/services/diaries.py, apps/diary/services/entries.py, apps/diary/views.py

Every diary, membership, or entry read and write goes through this module and a service in apps/diary/services/. The checks do not read staff or superuser flags. A person who cannot read the diary or the entry gets 404, including a staff user who is not a member. A member who lacks the action gets 403. Both leave the database unchanged. The 403 page is templates/403.html.

Django admin lists every diary and membership for support. It does not call this module. The admin is read-only, and it does not list entries.

readable_diaries is the diaries that person belongs to. get_readable_diary raises 404 otherwise.

The role table is product_brief.md Section 4.2. These functions encode it. Entry functions take the entry's current owner. Invite, role-change, transfer, and delete-diary functions have no screen. Entry reads, edits, and deletes do.

Rename is not a row in the product table. Only the Owner can rename.

A person sets defaults only on diaries they can read. Posting any other id returns 404 and changes nothing. Any subset may be the defaults, including none.

Entries​

readable_entries is the entries in a diary that person can read. An entry in two of those diaries is one row. readable_entries_for is that queryset limited to one diary when the day page asks for one. The day page, its calendar marks, and its list of days use it. get_readable_entry raises 404 otherwise. Edit is offered on Raw view only when the viewer is the current owner, which is the same rule as can_update_entry for a row already limited to entries they can read.

can_update_entry is true only for the current owner of an entry they can read. Another member gets 403 on save. The referenced date and the diary list are part of that same save. A posted diary they cannot read returns 404. A diary they can read but cannot add to returns 403. Either way nothing is written. Diaries they cannot read stay on the entry. The posted list has to include at least one diary they can add to.

can_delete_entry is true when any one of the entry's diaries grants can_delete_own_entry or can_delete_any_entry. The delete then removes the entry from every diary, including one the actor cannot read. Build plan #11 still has to decide whether a shared-diary delete should instead remove only that diary's membership.

How the save and the revision check behave is on Entries and autosave. can_edit_attributes has no screen. Organization attributes are not built.
