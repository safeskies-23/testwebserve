Local setup

Read this for: installing dependencies, starting Postgres, and opening the Django server or the docs site.

Source files: requirements.txt, .env.example, docker-compose.yml, .vscode/tasks.json, /Users/safeskies/Programming/Utilities/Docusaurus/package.json

Application dependencies are in the root requirements.txt. Each line pins the installed version. Documentation dependencies are in the shared Docusaurus app. Installing one does not install the other. This repository has no Node project.

Django application​

Use Python 3.14. From the repository root:

python3.14 -m venv .venv
source .venv/bin/activate
pip install -r requirements.txt
cp .env.example .env
docker start development-postgres
python manage.py migrate
python manage.py runserver

Set DJANGO_SECRET_KEY and POSTGRES_PASSWORD in .env before migrate. Set DJANGO_DEBUG=true while developing. To send mail, set DJANGO_EMAIL_HOST, DJANGO_EMAIL_HOST_USER, and DJANGO_EMAIL_HOST_PASSWORD. Leave the user or the password empty and development prints mail to the console. What each variable does is in Configuration.

Postgres runs only in Docker. Do not install it with Homebrew. A local server takes port 5432, and this project will not use it. This Mac’s database is the container development-postgres and the named volume development_postgres. It is already running and publishes port 5432. docker start development-postgres starts it again if it is stopped. runserver uses that database, on port 8000 for the app. The compose file in this repository is the homelab stack. It does not start development-postgres. Do not run docker compose up on this Mac.

Open http://127.0.0.1:8000/. The page asks you to sign in. python manage.py createsuperuser asks for an email and a display name. New accounts default to the UTC timezone. Django admin is at http://127.0.0.1:8000/admin/. From a user's row, Send set-password email sends the link through the mail backend in Configuration. Sign-in behavior is on Authentication.

Documentation site​

The docs site needs Node.js 20 or newer. It is the Pebble Diary site in /Users/safeskies/Programming/Utilities/Docusaurus, and it reads this repository's docs/ folder. From that app:

npm install
npm run start:pebble-diary

npm run start:pebble-diary serves this site at http://localhost:3001/ with live reload, bound to 0.0.0.0. npm run build:pebble-diary writes the static site to sites/pebble-diary/build. npm run serve:pebble-diary previews that build. npm run clear:pebble-diary drops the generated cache. CopperDraw stays on port 3000 via npm run start:copper-draw. A command names its site. There is no bare npm start.

The Django app and this static site are separate processes. The docs site stays on this computer. The privacy page linked from the app is the Django page, not this site.

The Compose file is the homelab stack. How an update ships is on Deploy.

Cursor tasks​

.vscode/tasks.json defines Start servers. It starts Django server and Docs site. Docs site runs npm run start:pebble-diary with its working directory set to the shared Docusaurus app. Docusaurus opens the browser. The Django task waits until runserver prints Starting development server at, then runs open http://127.0.0.1:8000/. Django server does that half on its own.

Both docs sites can run at the same time. Both Django projects use port 8000, so only one of them runs at a time.

Search runs in the browser from an index produced at build time. Mermaid diagrams in fenced code blocks are rendered by the site.
