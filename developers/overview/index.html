Overview

Read this for: the product boundary, which Django app owns a feature, the stack, and behavior that is named but not implemented.

Source files: apps/accounts/models.py, apps/accounts/views.py, apps/accounts/admin.py, apps/diary/models.py, apps/diary/permissions.py, apps/diary/services/diaries.py, apps/diary/services/entries.py, apps/diary/views.py, config/settings.py, config/urls.py

Pebble Diary is one Django project and one Postgres database. accounts owns the custom user, sign-in, settings, and the one row of site settings. diary owns diaries, memberships, entries, the permission module, and the diary services. config owns settings, root URLs, ASGI, and WSGI. It has no feature models.

People sign in with email and password, keep private diaries, and write entries. The write page saves while the person types. After sign-in they land on today's day page, with a calendar and Raw and Diary views. Django admin edits users and site settings, and it lists diaries and memberships read-only. It does not list entries. Sign-in behavior is on Authentication. Fields are on Models. Access checks are on Permissions. Saving an entry is on Entries and autosave. The day page is on HTMX and templates.

accounts stores the user and the site-settings row. diary stores diaries, memberships, and entries.

Boundaries​

PieceOwnsLeaves elsewhere
accountsUser, SiteSettings, sign-in, password reset, settings, registration, user adminEntries and the day page
diaryDiaries, memberships, entries, permissions, diary services, the Diaries page, the write page, and the day pageUsers, sign-in, security headers
configSettings, root URL routing, the theme context processor, the client-IP callableFeature models

Import the apps as apps.accounts and apps.diary. Their labels stay accounts and diary. AUTH_USER_MODEL is accounts.User. The email is the login, stored in lowercase. A display name is required. New accounts default to the UTC timezone.

There is no HTTP API. Views return server-rendered HTML. The day page uses HTMX to swap its panel. The editor does not.

Stack​

  • Python 3.14, Django 6.1, Postgres through psycopg 3
  • HTMX through django-htmx, with the script self-hosted at static/js/htmx.min.js
  • django-axes throttles sign-in. The numbers are on Authentication
  • One stylesheet, static/css/app.css, and self-hosted Source Sans 3
  • WhiteNoise and Gunicorn are dependencies. Local development uses runserver
  • Time zone support is on. The project time zone is UTC

The docs site is the Pebble Diary site in the shared Docusaurus app at /Users/safeskies/Programming/Utilities/Docusaurus. The site directory is sites/pebble-diary/. It reads this repository's docs/ and is not part of the Django process. Node dependencies stay in that app.

Directory ownership is on Layout. Environment variables and headers are on Configuration. The theme mechanism is on HTMX and templates.

Not built​

These rows, flags, and apps exist and do nothing that a person can use. They are named so they are not mistaken for current behavior. The intended features are on Roadmap.

  • User.appearance stores system, light, or dark, and defaults to system. The only designed theme mode is light, so every page renders light. Settings has no appearance control.
  • Entry.processing_instructions is an empty text column. No form field writes it. Processing is not built.
  • Permission functions for invites, role changes, ownership transfer, and deleting a diary exist and have no screen. Diary has no shared flag.
