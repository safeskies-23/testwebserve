Configuration

Read this for: what .env changes, and which security headers every response sends.

Source files: config/settings.py, config/client_ip.py, .env.example

config/settings.py reads .env from the repository root when that file exists. A variable already set in the environment wins. .env stays untracked. Do not put real secrets in docs or in .env.example.

USE_TZ is on. The project time zone is UTC. A user's own timezone is a field on the user, not an environment variable.

A normal session lasts 14 days from the last response (SESSION_COOKIE_AGE and SESSION_SAVE_EVERY_REQUEST). Password-reset links expire after one hour (PASSWORD_RESET_TIMEOUT). Sign-in throttling is on Authentication.

The production check from the repository root:

DJANGO_DEBUG=false DJANGO_PRODUCTION=true DJANGO_ALLOWED_HOSTS=example.com python manage.py check --deploy

Gunicorn is gunicorn config.wsgi:application. It is not how local development runs.

WhiteNoise serves static files. Outside production it uses Django's finders, so an app file such as apps/diary/static/diary/autosave.js is served without collectstatic. Production collects files into staticfiles/ and does not use the finders.

Mail​

EMAIL_BACKEND is DJANGO_EMAIL_BACKEND when that variable is set. Otherwise production uses SMTP. Development uses SMTP when DJANGO_EMAIL_HOST, DJANGO_EMAIL_HOST_USER, and DJANGO_EMAIL_HOST_PASSWORD are all set, and prints mail to the console when any of them is empty. Password reset and the change notices use that backend. The messages are on Authentication.

Development mail is a Gmail account: host smtp.gmail.com, port 587, TLS. The password is a Google app password, created in the Google account under Security. Restart runserver after changing .env. A reset link uses the address you opened in the browser, so a link sent from this Mac points at 127.0.0.1.

Security headers​

Every response from the home page sends:

  • Content-Security-Policy with default-src, script-src, style-src, font-src, img-src, connect-src, form-action, and base-uri set to 'self'; object-src 'none'; frame-ancestors 'none'. The policy has no unsafe-inline and no unsafe-eval.
  • Referrer-Policy: same-origin
  • X-Content-Type-Options: nosniff
  • X-Frame-Options: DENY

Session and CSRF cookies are SameSite=Lax. The session cookie is HttpOnly. A shared-device sign-in leaves the session cookie without an expiry date.

DJANGO_PRODUCTION also turns on SECURE_SSL_REDIRECT, secure session and CSRF cookies, and HSTS for one year with subdomains and preload. It treats X-Forwarded-Proto: https as a secure request, which is how the homelab proxy tells Django that TLS already ended. Leave it off for runserver.

config/client_ip.py returns REMOTE_ADDR. The sign-in lock uses that address, so a client cannot pick a different one by sending a forwarded-for header. django-axes uses that callable.

How the Content Security Policy constrains templates is on HTMX and templates.
